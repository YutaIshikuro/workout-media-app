# spec駆動開発ポリシー

`.kiro/specs/` の承認済み spec が実装の契約である。エージェントの判断で spec を黙って逸脱しない。

## 参照順序

**制約の正本は `/AGENTS.md` である。** ここには制約の中身を書かない。何を、どの順で読むかだけを指示する。

1. `/AGENTS.md` — 技術スタック、禁止 API、設計制約、テスト戦略、スコープ外。**矛盾したときは常にこれが勝つ**
2. `.kiro/steering/roadmap.md` — スペックの分割と依存順序、どのスペックが何を所有するか
3. `.kiro/steering/` の残り — `exercise-seed.md`（シードデータ）、`spike-findings.md`（Phase 0 の測定値。存在する場合）
4. `.kiro/specs/<feature>/requirements.md` — 何を満たすか
5. `.kiro/specs/<feature>/design.md` — どう作るか。File Structure Plan がファイル配置の正
6. `.kiro/specs/<feature>/tasks.md` — 作業単位と完了条件

`AGENTS.md` の内容をこのファイルや計画に書き写さない。参照して従う。

## 原則

| 原則 | 基準 |
|------|------|
| タスク境界を守る | 指示されたタスク番号配下のサブタスクだけを実装する。先のタスクに手を出さない |
| 設計が先 | 実装中に design.md との矛盾を見つけたら、実装で押し切らず矛盾を報告する |
| 所有 spec を侵さない | 他 spec が所有する契約（リポジトリ層 API、ルーティング、テーマトークン、eas.json）を勝手に変更しない。所有者は `roadmap.md` の Specs 一覧と各 brief の Out of Boundary にある |
| レイヤーを飛ばさない | UI → SQL / UI → `expo-media-library` の直呼びを作らない。必ずリポジトリ層・アダプタを経由する |
| ロジックを React に依存させない | `/AGENTS.md` §0。判定基準は「この関数を Node の vitest から呼べるか」 |
| 仕様書を書き換えない | `requirements.md` / `design.md` / `tasks.md` は仕様であって実装メモではない |

## 実装前に確定させること

実装してからレビューで設計上の欠陥を指摘されると、修正ではなく再設計になり、計画からやり直す周回が発生する。以下は**実装に着手する前に**方針を決め、計画に明記する。

| 論点 | 決めること |
|---|---|
| **純粋関数とアダプタの境界** | 書こうとしている各モジュールが、ロジック層（`react` / `react-native` / `expo-*` を import しない）とアダプタ層のどちらに属するか。**先に決める**。後から剥がすと import の連鎖で広範囲の書き換えになる |
| **テストの実行環境** | そのテストが Windows の vitest で動くのか、CI の Maestro でしか動かないのか、実機でしか確認できないのか。3 つのどれかを各テストについて宣言する |
| レイヤー境界 | 新しい型をどの層に置くか。層をまたぐデータ変換をどこが担うか |
| 契約の所有者 | 触る型・API を所有している spec はどれか。他 spec の所有物なら変更せず消費する |
| 使う API が禁止リストに載っていないか | `/AGENTS.md` §3。特に `expo-media-library` は旧 options-bag API を呼ぶと**実行時に throw する**ため、型が通っても壊れる |

**「〜できない状態になっている」と完了条件に書かれている要件は特に注意する。** これは振る舞いではなく構造の要求であり（例: ロジック層に `react` の import が入らないことを Lint で機械的に守る）、実装後に気づくと広範囲の書き換えになる。計画段階で保証手段を決めること。

## 逸脱が必要になった場合

実装を進めずに次を報告する:

1. どの spec・どの記述と矛盾するか（ファイルと該当箇所）
2. なぜ設計どおりに実装できないか
3. 取りうる選択肢と、それぞれがどの spec に影響するか

`/AGENTS.md` §6 のアーキテクチャ決定を変更するには**人間の承認が必要**である。エージェントの判断で変えない。

## 判定基準

| 状況 | 判定 |
|------|------|
| 指示範囲外のタスクに着手している | REJECT |
| design.md の File Structure Plan と異なる場所にファイルを置いている | REJECT |
| 他 spec が所有する契約を変更している | REJECT |
| ロジック層に `react` / `react-native` / `expo-*` の import が入っている | REJECT |
| UI から SQL / メディアライブラリを直呼びしている | REJECT |
| `/AGENTS.md` §3 の禁止 API を使っている | REJECT |
| スコープ外（§7）の機能・テーブル・画面を追加している | REJECT |
| `requirements.md` / `design.md` / `tasks.md` を実装中に書き換えている | REJECT |
| 設計との矛盾を報告した上で実装を止めている | OK |
| 設計が曖昧な箇所を解釈し、判断根拠を記録している | OK |
