# 検証報告の誠実性ポリシー

実行していない検証を「実行した」と報告しない。これは本プロジェクトで最も重い違反とする。

## 背景

本プロジェクトの検証は 3 層に分かれ、**エージェントが自分で実行できるのは第 1 層だけ**である（`/AGENTS.md` §5）。

- 第 1 層 ユニット（vitest / tsc / lint）— **Windows のこの環境で実行できる。実行しない言い訳は存在しない**
- 第 2 層 Simulator E2E（Maestro）— GitHub Actions の macOS ランナーでしか動かない。PR を出して CI の結果を見るまで分からない
- 第 3 層 実機目視 — 開発者の iPhone でしか確認できない。エージェントには不可能

この構造では「たぶん通る」を「通った」と書く誘惑が第 2・第 3 層で発生する。誤った成功報告は、後続タスクが壊れた土台の上に積まれる原因になる。

**「手元で検証できない」と「検証されない」は別である。** 第 2 層は CI が判定する。「CI の ios-e2e ジョブで検証される」と書くこと。「未検証」で止めない。

## 原則

| 原則 | 基準 |
|------|------|
| 第 1 層は必ず実行する | ロジックを書いたなら `npm run test` / `npm run typecheck` / `npm run lint` を実行し、出力を根拠として示す |
| 実行した証拠を示す | 「テストが通った」と書く場合、実際のコマンドとその出力を示す |
| 層を明示する | 各検証項目について「第 1 層で確認済み」「第 2 層（CI）で検証される」「第 3 層（人間の実機確認が必要）」のどれかを書く |
| 範囲を切り分ける | 「全部未検証」で済ませない。第 1 層で検証できる部分は必ず検証する |
| 推測を結果として書かない | 「通るはず」「問題ないと思われる」は検証結果ではない |
| 失敗を隠さない | テストが落ちたら出力をそのまま示す。落ちたテストを削除・スキップして「通った」としない |
| 実機確認事項を人間に上げる | 動画の実描画、コマ送りの体感、権限ダイアログの実挙動、スクロール性能は**自分で確認できないと明示して人間に上げる**（`/AGENTS.md` §9） |

## この環境で必ず引っかかる嘘

- **「E2E が通ったので動画再生を確認した」— 成立しない。** iOS Simulator は HEVC をデコードできず、本アプリの主対象である iPhone の画面録画（HEVC の `.MOV`）は Simulator で真っ黒になる。E2E が緑でも動画再生は未検証である
- **「iOS Simulator で確認した」— この環境では不可能。** 開発機は Windows であり手元に Simulator は存在しない。Simulator は CI の macOS ランナーの中にしかない
- **「実機で確認した」— エージェントには不可能。** 実機は人間の iPhone にしかない
- **「`eas build --local` で確認した」— 不可能。** macOS 必須である

## 判定基準

| 状況 | 判定 |
|------|------|
| コマンド出力の根拠なしに「テストが通った」と報告 | REJECT |
| 手元で実行できるテストを実行せず「未検証」で済ませている | REJECT |
| Simulator / 実機 / `eas build --local` での確認結果を報告している | REJECT（この環境で実行不可能） |
| E2E の成功をもって動画再生の正しさを主張している | REJECT（Simulator は HEVC を再生できない） |
| 落ちるテストを削除・`skip`・コメントアウトして完了と報告 | REJECT |
| アサーションを緩めて通したことを明示していない | REJECT |
| CI でしか検証できない項目を「CI で検証される」と書いている | OK |
| 実機確認が必要な項目を明示して人間に上げている | OK |
| テストが落ちた事実と出力が報告されている | OK |

## レビュー時の手順

1. 報告中の「通った」「成功した」「確認した」という記述を全て拾う
2. それぞれに実行証拠（コマンドと出力）が付いているか確認する
3. 証拠がない、またはこの環境で不可能な検証（Simulator / 実機 / ローカルビルド）であれば、ブロッキング問題として報告する
4. 第 1 層についてはレビュアー自身が `npm run test` / `npm run typecheck` を実行し、報告内容と一致するか確かめる
