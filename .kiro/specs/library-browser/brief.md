# Brief: library-browser

> 制約の正本は `/AGENTS.md`。

## Problem

このアプリが解決したい元の課題は「ジムでベンチプレスの参考動画を見たいのに、カメラロールの中で埋もれていて出てこない」である。取り込みもタグ付けもプレイヤーも揃ったうえで、**目的の動画に数タップで到達する導線**がなければ、課題は解決していない。

利用場面はジムであり、セット間の短い時間に片手で操作される。深い階層を辿らせる、検索文字列を打たせる、といった設計は実用に耐えない。

なお、標準の写真アプリもフォルダ > アルバムの 2 段構造を持つため、**階層そのものは差別化ではない**。ここで効く差別化は「1 本の動画が複数種目に同時に現れる」ことと、参照切れを含む状態が一覧上で扱えることである。

## Current State

- メディアの一覧表示が存在しない
- グルーピング・検索・絞り込みの手段がない
- 初回起動時の空状態が未設計

## Desired Outcome

- アプリを開いてから目的の種目の動画一覧に到達するまでが数タップで済む
- 種目別のグルーピングが主軸として提示され、部位カテゴリ（8 種）で素早く絞り込める
- 日付別の見方にも切り替えられる
- 種目名（日本語名・英字エイリアス・略記）での検索ができる
- サムネイルのグリッド表示が、数百〜数千件でもスクロールが引っかからずに動く
- 一覧から動画をタップするとプレイヤーが開き、そのまま次 / 前へ辿れる
- 何も取り込んでいない初回状態で、次に何をすればよいかが明示される
- **参照切れのメディアが一覧上で識別でき、その場で「選び直す / 削除」を選べる**

## Approach

種目別グルーピングを主軸のタブとし、部位カテゴリ → 種目 → メディア一覧という 2 段の絞り込みで到達させる。部位カテゴリは横スクロールのチップとして常時見せ、1 タップで絞り込めるようにする。

日付別は副次的なタブとして提供する。参考動画の保存日は撮影日でも実施日でもないため、日付は主軸に据えない。ただし「先週保存したあれ」という探し方には有効であるため、切り替えとして残す。

サムネイルグリッドは仮想化リスト（FlashList など）で実装し、`media-library-sync` から受け取ったサムネイルを遅延読み込みする。**サムネイルはファイルパスではなく `SharedRef<'image'>` として渡され、ディスクキャッシュは `expo-image` が担う。** 数千件規模を想定するため、フルアセットの読み込みは詳細表示まで遅延させる。

空状態は 2 種類を扱う: (1) 何も取り込んでいない初回 — 取り込み導線へ誘導する、(2) 取り込み済みだが未分類のみ — タグ付け導線へ誘導する。

**参照切れメディアは一覧から隠さず、その位置に印を出す。** タップすると「選び直す / 削除」の 2 択が出て、選び直すと `media-library-sync` のシステムピッカーが開き、**既存のタグがそのまま新しいアセットに移る**。参照切れは種目別一覧の文脈の中で発見される（「ベンチプレスを見ようとしたら 1 本壊れている」）ので、その場で直せることが自然であり、専用の修復画面を作らずに済む。

一覧からプレイヤーへは、現在の絞り込み結果をメディアリストとして渡し、プレイヤー内のスワイプ遷移が同じ絞り込み文脈の中を移動するようにする。

**グルーピング・絞り込み・並び順・検索の組み立ては React に依存しない純粋関数として書く**（`/AGENTS.md` §0）。`local-data-store` のリポジトリ API を呼ぶための引数を組み立てる部分と、結果を表示用に整形する部分の両方が対象である。

## Scope

- **In**:
  - 種目別グルーピング一覧（種目ごとの件数とサムネイル代表）
  - 部位カテゴリによる絞り込み（横スクロールチップ、8 カテゴリ）
  - 日付別グルーピング一覧（タイムライン / 月別）
  - 種目名での検索（日本語名 + 英字エイリアス）
  - メディア種別（動画 / 画像）での絞り込み
  - サムネイルグリッド表示と仮想化・遅延読み込み
  - グリッド / リストの表示切替、サムネイルサイズ調整
  - 並び順の切替（新しい順 / 古い順）
  - メディア詳細（付与種目、保存日、再生時間などのメタデータ）
  - 空状態（未取り込み / 未分類）と次アクションへの導線
  - **参照切れメディアの識別表示と、その場での「選び直す / 削除」**
  - 未分類メディアへの導線（`tagging-workflow` へ）
  - プレイヤーへの遷移とメディアリストの受け渡し
  - ジムでの片手操作を想定した主要導線の配置
  - Maestro flow（部位絞り込み → 種目 → 一覧 → プレイヤー遷移、空状態、参照切れ表示）
- **Out**:
  - タグ付け操作そのもの（`tagging-workflow` が所有。導線のみ提供）
  - 動画再生の内部実装（`video-viewer` が所有）
  - 写真ライブラリからの取り込み処理（`media-library-sync` が所有。導線のみ提供）
  - お気に入り / コレクション機能
  - 統計・分析ビュー

## Boundary Candidates

- グルーピング表示（種目別 / 日付別）: 変更理由は情報設計の見直し
- 絞り込み・検索: 変更理由は蓄積件数の増大
- サムネイルグリッドと仮想化: 変更理由は表示性能
- 空状態とオンボーディング導線: 変更理由は初回体験の改善

## Out of Boundary

- タグを「付ける」機能を持たない。付いているタグで「探す」側のみ
- 再生の中身を持たない。プレイヤーを開くところまで
- 写真ライブラリに直接アクセスしない。すべて `local-data-store` のリポジトリ API と `media-library-sync` の提供物を経由する
- トレーニングの統計・進捗可視化を作らない

## Upstream / Downstream

- **Upstream**: `local-data-store`（グルーピングクエリ）、`media-library-sync`（サムネイルと参照状態、選び直しのピッカー）、`tagging-workflow`（タグが付いていることが前提）、`video-viewer`（遷移先）
- **Downstream**: なし（MVP の最終段）

## Existing Spec Touchpoints

- **Extends**: なし
- **Adjacent**: `tagging-workflow` と種目タグの多対多モデルを共有する。両者が同一のリポジトリ API を経由し、独自クエリを持たないこと
- **Adjacent**: `media-library-sync` とサムネイルの受け渡し方（`SharedRef<'image'>` の持ち回り）、および参照切れの選び直し導線の契約を合意すること
- **Adjacent**: `video-viewer` へ渡すメディアリストと現在位置の契約を合意すること

## Constraints

- 依存が最も多い最終段のスペックであり、上流 4 スペックの契約がすべて確定していることが前提
- メディア件数は数百〜数千件を想定。この規模でスクロールがフレーム落ちしないこと
- ジムでの片手・短時間操作が主要な利用場面。深い階層と文字入力への依存を避けること
- 参照切れ状態のメディアが一覧に混在しうる。UI がこの状態を扱えること
- **スクロール性能の確認は実機目視のみ**（Simulator の性能値は当てにならない）
- **グルーピング・絞り込み・検索のロジックは Node の vitest から直接呼べること**
