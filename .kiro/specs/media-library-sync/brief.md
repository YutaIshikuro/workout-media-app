# Brief: media-library-sync

> 制約の正本は `/AGENTS.md`。禁止 API（旧 media-library API、expo-video-thumbnails）に特に注意。

## Problem

参考動画は iPhone の写真ライブラリの中に、家族写真やスクリーンショットと混ざって埋もれている。アプリがそれらを取り込まなければ何も始まらない。

同時に、本プロジェクトの技術リスクがここに集中している。`expo-media-library` が返すアセット ID（`localIdentifier`）は iCloud 復元をまたぐと切れることが知られており、iOS バージョン更新時にずれた報告もある。参照のみの構成を採る以上、**ID が切れた瞬間にユーザーが積み上げたタグが孤児になる**。

加えて iOS 14 以降の限定アクセス（`accessPrivileges: 'limited'`）では、ユーザーが選んだアセットしか見えない。

## Current State

- 写真ライブラリへのアクセス手段が一切存在しない
- 権限リクエストのフローが未設計
- サムネイルの取得機構がない
- 参照切れをどう検出し、どう回復するかが未設計

## Desired Outcome

- 初回起動時に写真ライブラリの権限を要求し、限定アクセス・全件アクセス・拒否のいずれの結果でもアプリが破綻せず、ユーザーに次の行動が提示される
- **システムピッカーから筋トレ動画を選ぶだけで、それがそのまま取り込みになる**
- 取り込んだ各メディアのサムネイルが表示され、一覧が実用的な速度で描画される
- 既に取り込み済みのアセットを再度選んでも重複が発生しない
- 参照切れが起きたメディアを検出し、「参照切れ」として UI に提示できる
- 参照切れメディアをユーザーが選び直すと、**既存のタグがそのまま新しいアセットに移る**
- 再同期を実行しても既存のタグが失われない

## Approach

**取り込みの入口をシステムピッカーに統一する。** このアプリは写真ライブラリ全体を勝手に取り込むのではなく、ユーザーが筋トレ動画を選んで取り込む。iOS の限定アクセスの再選択ピッカーは、まさにその「選ぶ」操作そのものであり、**それを縮退状態ではなく主経路として設計する**。これにより「数千件の中から筋トレ動画を選ぶ UI」を自前で作る必要がなくなる。

代償として、ピッカーがライブラリ全体を表示するのは iOS 側の仕様で JS から制御できず、取り込み済みかどうかがピッカー上で区別できない。**取り込み側でアセット ID による重複排除を行う**。

`expo-media-library` は**ルートから** import する（`/next` サブパスは存在せず、旧 options-bag API はルートから呼ぶと実行時に throw する）。`Query` クラスと `Asset` / `Album` のオブジェクト指向 API を使い、数千件のメタデータ一括取得には SDK 57 の `Query.exeForMetadata()` を使う。

サムネイルは `expo-video` の `VideoPlayer.generateThumbnailsAsync()` で生成し、返ってきた `SharedRef<'image'>` を `expo-image` の `source` に**そのまま渡す**。**ファイルとして永続化せず、ディスクキャッシュは `expo-image` に任せる。** DB にパス列を持たず、失効・容量管理も実装しない。

**参照切れは検出するが、自動再照合は実装しない。**

1. アセット ID による取得を試みる
2. 失敗したメディアを「参照切れ」状態にする
3. ユーザーが一覧から「選び直す」を選ぶとシステムピッカーが開き、選んだアセットに**既存のタグをそのまま移す**

作成日時・再生時間・ファイル名による自動同定は書かない。発火条件（iCloud 復元、iOS 更新）が開発中に再現できず、書いたコードの正しさを確認する手段がないためである。ただしそれらのメタデータは後から遡って取得できないので、`local-data-store` のスキーマに最初から保持する。

差分同期は、前回同期時刻以降に追加されたアセットのみを走査する形とし、毎回の全件スキャンを避ける。

## Scope

- **In**:
  - 写真ライブラリ権限のリクエストフローと 3 状態（`limited` / `all` / `none`）のハンドリング
  - **システムピッカー（`presentPermissionsPicker()`）を主経路とした取り込み**と、その説明 UI
  - 権限拒否時の案内と設定アプリへの導線
  - 取り込み時のアセット ID による重複排除
  - `Query` API によるアセットのメタデータ取得（`exeForMetadata()` の活用）
  - Info.plist の usage description の文言定義（config plugin / app.config.ts 経由）
  - `generateThumbnailsAsync()` によるサムネイル生成と `expo-image` への受け渡し
  - 差分同期（前回同期以降の新規アセットの検出）
  - 参照切れ検出と `local-data-store` への状態反映
  - 参照切れメディアの選び直しと**タグの引き継ぎ**
  - iCloud 最適化により端末に実体がないアセットのハンドリング（ダウンロード待ち・失敗）
  - **実機での限定アクセス挙動の検証**（アプリ再起動後の再要求バグの有無。Phase 0 スパイクの結果を引き継ぐ）
  - Maestro flow（`permissions: { photos: limited }` での権限フローと取り込み）
- **Out**:
  - **自前の取り込み対象選択 UI**（システムピッカーが担う）
  - **サムネイルのファイル永続化・キャッシュ失効・容量管理**（`expo-image` が担う）
  - **参照切れの自動再照合ロジック**
  - 種目タグの付与（`tagging-workflow` が所有）
  - 取り込んだメディアの一覧表示・グルーピング（`library-browser` が所有）
  - 動画の再生（`video-viewer` が所有）
  - メディアのアプリ内コピー

## Boundary Candidates

- 権限管理（要求、状態判定、システムピッカー）: 変更理由は iOS のプライバシー仕様変更
- アセット取り込み（走査、重複排除、差分同期）: 変更理由は取り込み条件の見直し
- サムネイル取得: 変更理由は expo-video / expo-image の API 変更
- 参照整合性（切れ検出、選び直し）: 変更理由は回復体験の改善

## Out of Boundary

- 種目の分類・推論に一切関与しない。メディアを取り込み、参照を健全に保つことだけを担う
- 表示レイアウトを決定しない。サムネイルと状態を提供するのみ
- アプリ内コピー方式への切り替えは行わない。ただしリポジトリ層 API を通すことで将来の切り替えを阻害しない

## Upstream / Downstream

- **Upstream**: `app-foundation`（骨格）、`local-data-store`（メタデータの書き込み先とリポジトリ API）、`eas-delivery`（カスタム権限文言には dev client が必要）
- **Downstream**: `tagging-workflow`（取り込み済みメディアがタグ付けの対象）、`video-viewer`（アセット URI の供給元）、`library-browser`（サムネイルと参照状態の消費者）

## Existing Spec Touchpoints

- **Extends**: なし
- **Adjacent**: `local-data-store` のスキーマに「参照状態」「再照合の手掛かりとなるメタデータ（作成日時 / 再生時間 / ファイル名）」が必要。両スペックで表現を合意すること
- **Adjacent**: `library-browser` とサムネイルの受け渡し方（`SharedRef<'image'>` をどこまで持ち回るか）の契約を合意すること

## Constraints

- **`expo-media-library` はルートから import する。`/legacy` と旧 options-bag API は使わない**（ルートからの呼び出しは実行時に throw する）
- **サムネイル生成は `expo-video` の `generateThumbnailsAsync`。`expo-video-thumbnails` と `expo-av` は使わない**
- `localIdentifier` は恒久キーではない。iCloud 復元・iOS 更新で切れうる前提で設計する
- 限定アクセス下で機能が成立すること。**むしろ限定アクセスが主経路**
- **限定アクセス許可済みでもアプリ再起動後に再要求される不具合報告がある。Phase 0 スパイクで検証し、壊れていれば全件アクセス併用に方針を戻す**
- 権限説明文をカスタムするため Development Build が必須（`eas-delivery` の完了が前提）
- ネイティブ依存の追加により dev client の再ビルドが発生する。EAS 無料枠（15 ビルド/月）を消費するため依存追加はまとめて行う
- iCloud の「iPhone のストレージを最適化」設定下では、アセットの実体が端末にない場合がある
- **Simulator E2E では動画の実描画を検証できない**（HEVC 非対応）。取り込みと権限フローの回帰検出に留め、動画の実体確認は実機で行う
