# Brief: video-viewer

> 制約の正本は `/AGENTS.md`。コマ送りの実装方法（`seekBy` ではなく `currentTime`）に特に注意。

## Problem

参考動画を保存する目的は「フォームを見て真似すること」である。標準の写真アプリのプレイヤーでは、この用途に必要な操作ができない。数秒の動作を繰り返し見たい、切り返しの一瞬を止めて見たい、速い動作をスローで追いたい——いずれも標準プレイヤーでは面倒か不可能である。

**プレイヤーは本アプリの差別化 3 点のうち最も代替が効かないものである。** 分類は写真アプリのフォルダ + アルバムでもある程度できるが、ループ・0.25x・コマ送りは代替がない。ここが標準プレイヤーと同等なら、このアプリを使う理由が大きく減る。

## Current State

- 動画再生機能が存在しない
- プレイヤーの操作要件が未定義
- **コマ送りの実現可能な粒度が未確定**（Phase 0 スパイクの測定項目 ①）

## Desired Outcome

- 一覧から動画を開くと、全画面のプレイヤーで再生が始まる
- ループ再生がデフォルトで、短い動作を何度でも見返せる
- 再生速度を落として（0.25x など）動作を細かく追える
- コマ送り / コマ戻しで、切り返しの一瞬を静止して確認できる
- シークバーで任意の位置に素早く移動でき、短い動画でも精密にスクラブできる
- 縦持ち・横持ちの両方で見られる
- プレイヤーを閉じずに、次 / 前の動画へ移動できる
- ジムで片手で操作できる（操作要素の配置とサイズ）

## Approach

`expo-video` をベースに専用のフルスクリーンプレイヤーを実装する。

デフォルト挙動をこのアプリの用途に合わせる。標準プレイヤーは「1 回再生して終わる」が前提だが、参考動画は「繰り返し見る」が前提であるため、**ループを既定にする**。

**コマ送りは `seekBy()` ではなく `player.currentTime += step` で実装する。** 公式ドキュメントが「フレーム精度が必要なら `currentTime` を使え」と明記しており、`seekBy` にはオーバー/アンダーシュートの報告がある。`expo-video` に動画の fps を返す API は存在しないため、ステップは固定値の仮定（例: 1/30 秒）とし、その根拠をコードのコメントに書く。

**実現可能な最小ステップは Phase 0 スパイクで実測する**（`.kiro/steering/spike-findings.md`）。フレーム単位の厳密な制御ができない場合、要件を実測値まで落とす。それでも実用にならないなら、コマ送りを Desired Outcome から外す判断もありうる。

精密シークには `scrubbingMode` を使う。iOS ではスクラブ中に pause し、ドラッグ終了時に `scrubbingModeEnabled` を false に戻す。`seekTolerance` はデフォルト（`0` = 正確な位置へシーク）を維持する。

一覧との往復を減らすため、プレイヤー内で次 / 前の動画にスワイプ遷移できるようにする。

画像（静止画）も取り込み対象であるため、動画と画像で同じビューア導線に入り、画像の場合はズーム / パン中心の表示に切り替わる形とする。

**再生エンジンのラッパー（expo-video の抽象化）と、コマ送りのステップ計算・速度の段階・シーク位置の算出は、React に依存しない純粋関数として分離する**（`/AGENTS.md` §0）。

## Scope

- **In**:
  - `expo-video` ベースのフルスクリーンプレイヤー
  - ループ再生（既定 ON、切り替え可能）
  - 再生速度変更（0.25x / 0.5x / 0.75x / 1x 程度）
  - **コマ送り / コマ戻し（`currentTime` ベース、スパイクで実測した最小ステップ）**
  - 精密シークバー（`scrubbingMode` を用いた短尺動画でのスクラブ）
  - 再生 / 一時停止、タップでの操作コントロール表示・非表示
  - 横向き（landscape）対応と回転時の挙動
  - 次 / 前のメディアへのスワイプ遷移
  - 画像メディアのビューア（ピンチズーム、パン）
  - メディアのメタデータ表示（種目タグ、日付）とプレイヤーからのタグ編集導線
  - 参照切れメディアを開こうとした場合のエラー表示
  - iCloud 最適化で実体が端末にない場合のダウンロード待ち表示
  - 片手操作を想定したコントロール配置
- **Out**:
  - 2 動画の並列比較再生
  - 動画の編集・トリミング・書き出し・共有
  - 動画への描画・注釈（角度線、ガイドラインなど）
  - 音声の詳細制御
  - 一覧・グルーピング表示（`library-browser` が所有）

## Boundary Candidates

- 再生エンジンのラッパー: 変更理由は expo-video の API 変更
- フォーム確認用の操作機能（ループ・速度・コマ送り）: 変更理由は確認方法のニーズ変化
- ビューアのナビゲーション（次 / 前遷移）: 変更理由は導線設計の見直し
- 画像ビューア: 変更理由は静止画の扱いの変化

## Out of Boundary

- 動画の取り込み・アセット URI の解決は `media-library-sync` が所有する。ここは渡された参照を再生するのみ
- どの動画をどの順で見せるかの決定は `library-browser` が所有する。プレイヤーはメディアのリストと現在位置を受け取る
- タグの付与ロジックは `tagging-workflow` が所有する。プレイヤーからは編集画面への導線のみ
- 比較再生は明示的に作らない

## Upstream / Downstream

- **Upstream**: `app-foundation`（骨格）、`media-library-sync`（アセット URI と参照状態の供給）
- **Downstream**: `library-browser`（一覧からプレイヤーへ遷移する）

## Existing Spec Touchpoints

- **Extends**: なし
- **Adjacent**: `tagging-workflow` と並行実行可能。プレイヤーからのタグ編集導線でのみ接続する
- **Adjacent**: `library-browser` がプレイヤーへ渡すメディアリストと現在位置の契約を合意すること

## Constraints

- **`expo-video` を使う。`expo-av` の video API と `expo-video-thumbnails` は使わない**
- **コマ送りに `seekBy()` を使わない。`currentTime` を使う**
- **`expo-video` に fps を返す API は存在しない。** ステップは固定値の仮定とし、根拠をコメントに書く
- **🔴 このスペックは Simulator E2E で検証できない。** iOS Simulator は HEVC のハードウェアデコードを持たず、iPhone の画面録画は既定で HEVC の `.MOV` である。**動画再生の実描画は実機目視のみで確認する**
- 短い動画で `currentTime` の設定値と実際の到達値がずれる報告がある。スパイクで実測し、要件に反映する
- 画面録画由来の動画が主対象であるため、解像度・フレームレート・アスペクト比が不揃いである前提で扱うこと
- 参照切れ・実体未ダウンロードといった異常系がプレイヤー側にも到達する
- New Architecture 環境で動作すること
